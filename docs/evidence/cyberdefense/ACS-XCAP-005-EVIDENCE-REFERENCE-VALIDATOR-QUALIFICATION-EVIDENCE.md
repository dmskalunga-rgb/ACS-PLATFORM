## Security and architecture boundary

The validator is an internal typed call using canonical Machine/Service authentication and the canonical machine tenant-context issuer. It delegates the bounded existence/status question to XCAP-005. Its dedicated permission is not included in an evidence-table `SELECT` policy. A direct session holding only that permission sees no evidence rows. The SQL function checks the activated machine grant and returns one boolean; the service returns only `VALID` or `INVALID`. Cross-tenant, nonexistent and malformed references converge on `INVALID`. Authentication, authorization, issuance, repository and audit failures fail closed. Validation writes only a bounded canonical audit record, never evidence content, reference ID or protected metadata. There is no new evidence, event, credential, identity or MPA authority.
